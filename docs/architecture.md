# Архитектура

## Схема

```text
Телефон покупателя   ─┐
Кабинеты сотрудников ─┤→ nginx ─┬→ Nuxt (SSR) ──┐
                              └→ FastAPI ←────┘
                                    │
                                PostgreSQL
                                    ↑
                 Импорт выгрузки партнёра (famarket.ru/yml/)
```

## Решения

| Решение | Почему |
|---|---|
| Монорепозиторий `backend/`, `frontend/`, `deploy/` | Один разработчик, общие релизы и CI |
| Nuxt с серверным рендерингом | Быстрый первый экран на телефоне и задел под SEO |
| `$fetch` вместо axios | Работает и на сервере, и в браузере без отдельной настройки |
| Без vue-i18n | Интерфейс только на русском, добавим при появлении второго языка |
| Без ant-design-vue | Монохромный дизайн проще и легче собрать своими компонентами |
| Покупатель без аккаунта | Статус заказа открывается по ссылке со случайным токеном |
| Деньги в `Numeric` | Округления `float` недопустимы в заказах |

## Данные

```text
Category ── Product ─┬─ StockItem ── Warehouse
                     └─ SupplierOffer ── Supplier

ResidentialComplex ── Building

Order ─┬─ OrderLine ── OrderAllocation
       ├─ OrderServiceLine
       ├─ OrderEvent
       └─ User (курьер)
```

- `Product` — товар на витрине и цена продажи, источника в нём нет.
- `StockItem` — остаток на своём складе.
- `SupplierOffer` — закупочная цена и остаток партнёра. `product_id` пуст, пока предложение
  не сопоставлено с товаром.
- `OrderLine` — снимок названия и цены на момент заказа.
- `OrderAllocation` — откуда взято количество и за какую себестоимость. Одна строка может
  разделиться: 12 мешков со склада и 8 от партнёра.
- `OrderServiceLine` — доставка или подъём, цена для покупателя и расход клиента.
- `Building.code` — код корпуса для QR. `cargo_lift_length_mm` нужен для предупреждения о длинных листах.
- `Order.public_token` — случайный токен ссылки на статус. Номер заказа в ссылку не попадает.
- `Order.courier_id`, `planned_date`, `planned_slot` — кто и когда везёт. `cash_received` —
  сколько наличных курьер получил на месте.
- `OrderEvent` — история заказа: создан, смена статуса, назначение доставки, проблема.

## Сотрудники

Три роли с общим входом `/login`, после него каждый попадает в свой кабинет:

| Роль | Кабинет | API |
|---|---|---|
| `admin` — владелец | `/admin`: сводка, деньги, наценка, дома и тарифы, сотрудники | `/api/v1/admin` и `/api/v1/manager` |
| `manager` — менеджер | `/manager`: заказы, курьер и дата, каталог, партнёр | `/api/v1/manager` |
| `courier` — курьер | `/courier`: только свои доставки | `/api/v1/courier` |

Права проверяет сервер. Менеджер получает заказ через схему без прибыли, курьер на чужой
заказ получает 404. Интерфейс только прячет лишнее и перенаправляет в свой кабинет.

## Партнёр

У партнёра есть открытая YML-выгрузка, но нет API, насколько видно снаружи. Поэтому:

1. Импорт раз в час обновляет цены и остатки `SupplierOffer`.
2. Смотрим на `count`, а не на `available`: в выгрузке `available="true"` у всех товаров,
   хотя у 31% остаток 0 или меньше.
3. Менеджер подтверждает наличие у партнёра перед каждым заказом.
4. Если выгрузка сломалась, старые данные остаются и приходит уведомление. Остатки не обнуляем.
5. Использовать выгрузку, фото и описания можно только с письменного разрешения партнёра.

## Слои бэкенда

`api` → `services` → `repositories` → `models`. Правила каждого слоя лежат в его `README.md`.
Домены API: `platform` для покупателей, `manager`, `courier` и `admin` для сотрудников.

## Фронтенд

```text
frontend/app/
├── pages/         # маршруты, только композиция фич; admin/, manager/, courier/ — кабинеты
├── layouts/       # default — витрина, staff — владелец и менеджер, courier — курьер
├── features/      # catalog, cart, checkout, location, staff, courier: types, api, store, components
├── shared/        # http и общие компоненты
└── assets/scss/   # токены дизайна и база
```

## Окружения и выпуск

- Локально: `docker compose up` поднимает БД, API и Nuxt с перезагрузкой.
- Проверки: `ci.yml` на каждый push и pull request.
- Выпуск: push в `release` или тег `v*` собирает образы и публикует их в Docker Hub.
- Сервер: `deploy/update.sh` скачивает образы и перезапускает сервисы.
